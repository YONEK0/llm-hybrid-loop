## 一、目标

让 Qwen3-4B-Thinking-2507 通过**循环深度**（Recurrent Depth，共享层块反复迭代）实现
**隐空间推理**——模型不做显式思维链，把推理压缩进隐状态迭代中，最终目标：
各项指标接近甚至超过原模型的显式思维链水平。

## 三、实现

`recurrent_qwen.py`（核心模型，约 300 行）：

- 取 Qwen3-4B 的第 24–29 层（6 层）转为**共享循环块**，前面的 prelude（0–23 层）和
  后面的 coda（30–35 层 + LM head）保持原权重；
- 每轮迭代带独立 **rank-8 低秩增量**（DeltaSet），每轮循环前用 LatentInjection
  **重新注入 prelude 输出**（防止迭代漂移失忆）；
- 训练时随机深度采样（1..T）+ 每轮迭代的**深监督**（aux_weight=0.2）；
- `check_equivalence.py`：depth=1 时与原模型前向**精确等价（diff = 0.0）**，作为
  每次训练前的守门检查。

辅助实现：`train_curriculum.py`（脚手架课程训练，keep-steps 3→2→1→0 调度）、
`train_prosqa.py`、`train_direct.py`（scheduled-sampling 自滚动微调）、
`eval_scored.py` / `eval_fast.py` / `eval_compression_scaled.py` /
`eval_prosqa_ceiling.py` / `eval_ouro_depth.py` / `diagnose_extraction.py`。

## 五、评测过程与关键事件

### 5.1 常规评测（宽松评分阶段）

- ProsQA 30 题：底模@48token 56.7%、训练后@16token 56.7%、depth=4 3.3%、depth=8 0%；
- 由此得出"**token 压缩 3:1 不损准确率**"的头条结论（后被证伪）；
- Ouro 对照：Ouro-2.6B 深度 4 得 60%（宽松），Ouro-1.4B 得 36.7%。

### 5.2 收尾审计：评分伪影事件（2026-09-19，本项目最重要转折）

**发现过程**：做 n=150 扩展评测（加入底模@16token 公平对照 + Wilson CI + McNemar
配对检验）时，三个条件**逐题完全一致（+0/−0）**——两个不同模型、不同预算下统计上
几乎不可能，顺藤摸瓜定位到评分函数。

**机制**：`extract_prosqa_answer` 从后往前找第一个 `<Name> is a <thing>` 句式。
模型开头的复述句（"Okay, let's try to figure out if Eva is a lorpus or…"）被当答案
抽取；gold 恰好等于首个被提及的候选类时即记为正确。

**诊断**（`diagnose_extraction.py`，n=30，保存全文）：base@48 / base@16 / trained@16
三个条件各 17 个"正确"**全部**来自首行复述匹配；严格评分（仅认 `####` 后文本或
整行裸陈述句）下 **0/30**；抽检确认 0/30 篇全文任何位置都不存在裸答案行——
无误杀。同类伪影在 GSM8K 侧以"截断后取最后一个数字"的形式重演（见 5.3）。

**处置**：全面双标准重评；`eval_ouro_depth.py` 改为宽松+严格双输出；确立守门规则
——**凡自由生成评测，一律以严格抽取器为准**；四份文档全部修订，撤回伪影数字。

### 5.4 Ouro 深度-准确率扫描（严格口径重评后）

`eval_ouro_depth.py` 利用 Ouro 前向的 `exit_at_step` 参数扫描有效循环深度
（KV 缓存不变，仅换读出隐状态；ProsQA test 30 题）：

| 有效深度 | Ouro-2.6B（7.7T token 预训练） | Ouro-1.4B |
|---|---|---|
| 1 | 0% | 0% |
| 2 | 13.3% | 0% |
| 3 | 53.3% | 10.0% |
| 4 | **53.3%** | 20.0% |

深度单调增益在正确预训练的模型上真实存在（宽松口径的 60% 高估约 7 点；
1.4B"深度 1 反而最高 46.7%"的反常在严格口径下消失）。行为差异同样清晰：
深度 1–2 时 Ouro-2.6B 退化成显式文本推理开头（16 token 内答不完），深度 3–4 时
直接给出简洁最终句。

### 5.5 对照研究（视频方法核对）

截帧核对 B 站视频《recurrent depth，gpt-6-astra的新架构？让模型无声的思考》
（偷星九月333，BV1UqYJ6sErE）的训练配方：每轮深监督 + 损失加权 + PonderNet 式
退出门 + **退出门两阶段训练**（阶段一联合训练+熵正则；阶段二冻结主干、用相邻轮
损失下降量构造继续概率软标签做二元交叉熵）。结论：该配方是我们实现的完整版
（我们缺退出门两阶段训练这一块），其可行域为"从零预训练"与"服务器级 uptrain"，
不覆盖"冻结底模+8GB 后训练"（门无信号可学）。已写入 `RECURRENT_DEPTH.md` 附录。

## 七、错误总结（重点）

### 错误一：评分函数伪影——最严重，污染了全部历史"正结果"

- **现象**：所有自由生成"正结果"（56.7%、压缩 3:1 不损准确率、Ouro 60% 等）
  事后证实主要来自抽取伪影而非真实作答。
- **根因**：评测脚本里"从后往前找第一个 `X is a Y`"的宽松正则，会把模型**开头的
  问题复述**当成答案；GSM8K 侧"截断后取最后一个数字"把思考到一半的中间量当答案。
- **为什么没早发现**：伪影给出的数字（56.7%）恰好落在合理区间、且与底模一致，
  "看起来可信"；缺乏对评分器本身的效度检验；三个条件逐题完全一致这种反常
  只在把 n 扩到 150 并做配对检验时才暴露。
- **教训**：
  1. 自动评分器必须先用"模型必然答不对"的样本做对抗性效度检验；
  2. 禁止用会匹配到**题目内容**的正则给自由生成评分；
  3. 不同模型不同预算逐题完全一致 = 天然报警信号，见到必须先怀疑评测而非庆祝稳定。

### 错误二：评测协议缺陷（发现得太晚）

- **缺公平对照**：宣布"3:1 压缩成功"时从未跑过"底模@16 token"这个显然必要的对照；
- **训练内自由生成监控失灵**：`free_acc` 只在 depth=4 下评（恰是已知会崩的深度），
  暴露偏差全程未被观测，直到收尾才定性；
- **文档卫生**：引用了不存在的结果文件（base_model_baseline.json 数字无存档）；
  `control_disabled.py` 实际跑在 GSM8K 却被标成 ProsQA；
- **教训**：每个对比声明先问"对照组是什么"；n=30 且置信区间 ±18% 的数字不配当
  头条；文档里每个数字必须能溯源到落盘的结果文件；训练脚本的内嵌评测必须覆盖
  部署真实使用的配置。

### 错误三：方向性误判——低估了"能力在预训练中习得"的门槛

- 初始赌注是"复制权重 + 低秩增量 + 小数据微调"可把强底模改造成循环推理模型；
  实测循环块重复应用后表征偏离分布（加深反而更差），scheduled-sampling 600 步
  也修不好"只会复述不会作答"。
- **事后看，最早该做的实验是 Ouro 深度扫描这条对照链**（2.6B 有增益、1.4B 减半、
  本机改造为零），它一锤定音地勾出"循环推理能力 ∝ 预训练算力"的边界——
  这个实验排在项目最后，前期的多轮训练在方向存疑时就已经烧掉了大量时间。
- **教训**：遇到"某能力是否必须在预训练期习得"类问题，先用最便宜的自然对照实验
  验证边界，再投入训练资源。

### 错误四：工程环境损耗

transformers 版本连环不兼容（4.46→4.51→4.57，三层 shim）、bitsandbytes 与
Blackwell sm_120、GGUF 不兼容、Windows 路径问题、OOM（batch 32 → 4 + 梯度累积）、
GitHub 直连不可达。**教训**：开工前先锁定"目标模型自定义代码 × transformers 版本"
的兼容矩阵，并把它写进环境文档；否则每个坑都会以小时计。

### 错误五：伪影的间接代价——误导了中期决策

因为"56.7% 持平"的假象，中期的注意力放在"加深深度为什么变差"上，而没有立刻
追问"自由生成的模型到底在输出什么"。如果第 2 天就看一眼生成文本（复述句），
伪影当天就会暴露，scheduled-sampling 补救实验可以提前数天进行。

## 八、最终总结

1. **V1 目标未达成，且在本机约束下结构性不可达**：严格评分下，训练后模型自由生成为
   0%；V1 所采用的循环块改造配方没有学出接近原模型的循环不动点性质。Ouro-2.6B
   （7.7T token）严格 53.3% 且深度单调、Ouro-1.4B 减半、本机 V1 后训练为零，
   共同说明循环训练质量和规模是关键变量；这不是所有后训练 retrofit 方法的普适下界。
2. **真实留下的正资产**：(a) 教师强制下隐空间部分推理的证据（k=0 EM 0%→25%）与
   84% 的教师强制持平率；(b) 完整可迁移的训练代码（课程训练、scheduled-sampling、
   等价性守门）；(c) 从视频截帧补齐的退出门两阶段训练方案——V1 服务器 uptraining
   路线的最后一块拼图（约 150 行改动，方案已写入 `RECURRENT_DEPTH.md`；token 预算
   应按 LoopUS/V5 实测重估）；
   (d) 一条被反复教训过的评测纪律：严格抽取器守门、公平对照先行、数字必须可溯源。
3. **最大的收获是负结果的质量**：本项目最终交付的不是"接近原模型的循环推理模型"，
   而是一个被伪影审计反复锤打过的、每个数字都有协议和对照的 V1 边界——
   它明确指出：按旧配方继续在 8GB 笔记本上调参没有出路；服务器预算和训练方法应按
   LoopUS/V5 的实测重新估算，不能继续把 60B 当作普适门槛。

### 错误六（追加，2026-09-19）：未做"先例检索"，现成方案被漏掉

用户复盘时追问"难道前面其实有现成循环块，然后没复用？"——成立，分两层：

**第一层：Ouro 在本地却只当对照用。** Ouro-1.4B/2.6B（预训练循环模型）早已下载
在 `models/`，但 V1 全程只把它当作"证明深度增益存在"的参照系，从未考虑以它为
底敏做后训练强化。其中部分是目标约束（当时的目标就是改造 Qwen 血统的模型，
Ouro 是字节从零预训练的另一血统），但"预训练循环模型 + 后训练"这个方向本可
更早提出——直到收尾才形成 V2′ 方案。

**第二层（真失误）：LoopUS 存在了半年而我们没搜到。** LoopUS（arXiv:2605.11011，
2026-05，釜山国立大学）就是"Qwen3-1.7B/4B/8B 后训练循环化"：与我们 V1 完全同构
的架构（encoder/循环块/decoder）、同款底模之一（Qwen3-4B）、训练量仅 3B token、
代码与循环化模型权重全部开源。它的选择性门+单调性损失+随机深监督恰好是 V1
死因（表征漂移、深度增益为负、全 BPTT）的三个解药。V1 若开工前检索到它，
整轮"自研撞墙"可以替换为"复现+移植"，省下数天 GPU 与全部弯路。

**根因**：在 V1 阶段，文献调研的检索词聚焦在方法论（latent reasoning / recurrent depth /
Coconut / Relaxed Recursive），从未用工程化关键词（"Qwen looped" / "recast
pretrained LLM" / "retrofit recurrence post-training"）做过专项扫描；该子类
2025-11 至 2026-05 密集出了三篇（McLeish 2511.07384、LoopUS 2605.11011、
2608.11233），全部漏检。直到用户直接问"qwen 系列没人做过的？"才触发正确检索，
一击命中。

**教训**：立项时的文献调研必须包含一轮"是否有人已经做过目标组合"的显式检索
（目标底模家族 × 目标改造方式），关键词要覆盖论文常用的动词（recast/retrofit/
convert/adapt），不只搜概念名词。自研之前先假定"可能有人做过"，检索不到再动手。
