# 循环深度隐空间推理 — 研究总结

> **版本边界**：本文主要记录 V1 的 Qwen3-4B-Thinking 本机后训练结果。文中“60B–7700B
> token”是对当时自研配方和已测对照的资源判断，不是所有后训练循环化方法的理论下界。
> 后续发现的 LoopUS（Qwen3 后训练循环化，约 3B token）已改变路线判断；当前执行方案见
> [`TRAINING_PLAN_V5_HYBRID_LOOPUS.md`](../plans/TRAINING_PLAN_V5_HYBRID_LOOPUS.md)。

## 目标

让 Qwen3-4B-Thinking-2507 通过循环深度实现隐空间推理，各项指标接近或超过原始模型的显式思维链水平。

## 最终结论

**按 V1 的 8GB 本机配方无法实现“接近或超过原模型”的目标。** 该结论约束的是
冻结 4-bit 底模 + 低秩增量 + 小规模后训练的旧路线；不能外推为 LoopUS 配方或服务器级
Qwen3.8-27B 训练必然失败。

## 评分效度修订（2026-09-19，重要）

本次收尾审计发现：**ProsQA 自由生成的历史全部正结果由评分函数伪影构成**，已按严格
评分口径全面重测并修订本文档。

- **伪影机制**：`extract_prosqa_answer`（及 eval_ouro*.py 同款）从后往前找第一个
  `<Name> is a <thing>` 模式。模型开头的"Okay, let's try to figure out if Eva is a
  lorpus or..."复述句被当答案抽取；当 gold 恰好等于首个被提及的候选类时计为正确。
- **诊断**（`diagnose_extraction.py`，n=30，seed 11）：base@48 / base@16 / trained@16
  三个条件各 17 个"正确"**全部**来自首行复述匹配；严格评分（仅认 #### 后文本或整行
  裸陈述句）下全部 0/30。抽检确认 0/30 篇文本任何位置都不存在裸答案行——无误杀。
- **n=150 扩展评测**（`eval_compression_scaled.py`）：三条件逐题完全一致（McNemar
  +0/-0），同一伪影机制的指纹；严格口径结论不变（0%）。
- **Ouro 重评**（`eval_ouro_depth.py` 双标准）：见下方深度曲线表——浅深度的"得分"
  全部消失，深度单调性反而更干净。
- **底模天花板**：GSM8K 思考模式 256 token 仅 15% 且 15/15 为兜底伪影；GSM8K 1024 token
  达 **67%（严格 64%）**——64/100 题在预算内写完（EOS）且全部正确，宽松分中多出的 3 个
  全是"截断取末数字"碰对；直答 16 token 仅 2%。ProsQA 512 与 1024 token 均 0/30 完成
  （无一题在预算内生成结束）。**原模型在 ProsQA 上的实际可达分数 ≈0%（严格口径）；
  GSM8K 思考天花板 64%。**
- **新守门规则**：凡自由生成评测，一律以严格抽取器为准（`extract_answer_strict` /
  `extract_prosqa_answer_strict` 语义）；训练内教师强制评测不受影响。

## scheduled-sampling 直答微调（pd-v1，最后一个本机训练杠杆）

针对"只会复述、不会作答"的暴露偏差，实现了 scheduled-sampling 微调
（`train_direct.py`：从当前策略贪心 rollout ≤20 token → 随机截断 → 对答案段做
教师强制 CE；深度 1–4 随机采样；从 pq-v1 检查点续训，24.1M 可训练参数）。

| 训练量 | 严格自由生成 EM（dev，深度1，16 token） |
|---|---|
| 0 步（起点） | 0.0% |
| 200 步 | 0.0% |
| 400 步 | 0.0% |
| 测试集终评（30 题，深度 1 与 4） | **0/30** |

结论：scheduled sampling 400 步内未让模型学会在自身前缀之后输出 `#### 答案`。
结合"原模型在 ProsQA 实际可达分 ≈0%"的新发现，本机侧的全部 V1 训练杠杆（教师强制课程、
固定深度、scheduled-sampling）已穷尽，自由生成作答能力仍为 0%。这支持“V1 的循环不动点
性质没有被小规模后训练学到”，但不构成对 LoopUS 等其他 retrofit 配方的普适算力下界。

## 已完成的实验

### 实现

- Qwen3-4B-Thinking-2507（4-bit NF4）的层 24–29 转为循环块
- 每轮迭代带独立低秩增量（rank 8）
- 每轮循环前重新注入 prelude 输出
- 训练时随机采样循环深度（1..4）
- 深监督：每轮迭代后读出答案预测
- 等价性验证：depth=1 与原模型精确一致（diff = 0.0）

### 训练

| 运行 | 数据 | 步数 | 结果 |
|---|---|---|---|
| rd-v1 (GSM8K) | 1000 样本 | 600 | ce 9.3→0.54，token 48→16 |
| pq-v1 (ProsQA) | 10000 样本 | 1200 | ce 3.2→0.19，k=0 EM 0%→25% |
| fixed-d4 (ProsQA) | 2500 样本 | 600 | ce 0.32，EM 保持 40%→37% |

### 关键评测（ProsQA test，30 题，已按 2026-09-19 评分修订标注）

| 配置 | 宽松评分 | **严格评分** | Token | 说明 |
|---|---|---|---|---|
| 底模 @48 token（step-by-step 提示） | 56.7% | **0.0%** | 48 | 宽松分全是开头复述伪影 |
| 底模 @16 token（公平对照） | 56.7% | **0.0%** | 16 | 同上（n=150 逐题一致） |
| 训练后 depth=1 | 56.7% | **0.0%** | 16 | 只复述、不作答（暴露偏差） |
| 训练后 depth=4 / 8 | 3.3% / 0.0% | **0.0%** | 16 | 深度加深后表征崩坏 |
| 底模 @1024 token（天花板） | 10.0% | **0.0%** | 1024 | 0/30 在预算内写完 |

| 底模 GSM8K 思考 @1024 token（天花板，n=100） | 67.0% | **64.0%** | 785 | 64/100 EOS 内写完且全对；3 个"截断碰对"剔除 |

| 发现 | 含义 |

| ~~Token 压缩 3:1 不损准确率~~（撤回） | 宽松评分伪影；严格评分下自由生成为 0% |

## 在服务器上达成的路线图

### 硬件需求
- 至少 2× A100 80GB 或 4× A6000 48GB
- 训练量：60B token（Relaxed Recursive 最低要求）

### 步骤

1. **准备数据**：GSM8K train（7,473）+ Aug（额外合成），总 ~30K 样本
2. **初始权重**：从 Qwen3-4B-Thinking 的层 24–29 复制为共享块
3. **每轮迭代加 LoRA**：r=8，4 轮迭代 × 7 投影 = 28 个 LoRA 模块
4. **Uptrain 60B token**：batch 32，lr 1e-4，AdamW，bf16，深监督 aux_weight=0.1
5. **知识蒸馏**：从原始未循环模型做前向 KL 蒸馏
6. **评估**：ProsQA + GSM8K，对比原始模型

预期结果：达到底模 90%+ 的准确率，同时推理 token 减少 2–3 倍。

### 所需时间（4× A100）
- 60B token ÷ 4 卡 × ~2000 token/s/卡 ≈ **87 小时** ≈ 4 天
- 加上评估和调试，总计约 **1 周**

## Ouro 深度-准确率曲线（追加，ProsQA test 30 题）

利用 `modeling_ouro.py` 的 `exit_at_step=k` 前向参数：模型内部始终跑满 4 轮迭代（KV 缓存
不变），只改变用哪一轮的隐状态读出 logits，从而得到干净的"有效深度-准确率"曲线。
脚本：`eval_ouro_depth.py`；数据：`results/ouro_depth_sweep_Ouro-{1.4B,2.6B}.json`。

| 有效深度 | Ouro-2.6B 宽松 | Ouro-2.6B **严格** | Ouro-1.4B 宽松 | Ouro-1.4B **严格** |
|---|---|---|---|---|
| 1 | 26.7% | 0.0% | 46.7% | 0.0% |
| 2 | 40.0% | 13.3% | 30.0% | 0.0% |
| 3 | 56.7% | **53.3%** | 36.7% | 10.0% |
| 4 | 60.0% | **53.3%** | 36.7% | 20.0% |

两个关键发现（严格口径下依然成立且更干净）：

1. **Ouro-2.6B 的严格准确率随深度单调上升**（0%→13.3%→53.3%→53.3%）。宽松口径下
   浅深度的"得分"全部为复述伪影：深度 1–2 时模型只会生成"Okay, let's figure out..."
   式的显式推理开头，16 token 内没有任何真实答案；深度 3–4 时直接给出简洁最终句——
   循环迭代把显式推理替换成了隐空间推理。**这是"循环深度必须在预训练中习得"的正面
   对照**：我们在 Qwen3-4B 上后训练改造无法复现的深度单调增益，在 7.7T token 预训练
   的 Ouro-2.6B 上真实存在（严格 53.3%，此前宽松口径 60% 高估约 7 点）。

2. **Ouro-1.4B 严格曲线同样单调但水平低得多**（0%→0%→10%→20%）。此前宽松口径
   "深度 1 反而最高 46.7%"的反常完全消失。循环预训练的规模同样重要：小模型的循环块
   没有学到足够的不动点性质。这与我们 Qwen3 实验的负面结果同构。

结论：本研究的核心负面结果（后训练改造不达标）获得最强佐证——深度单调增益只在
"循环架构 + 海量预训练"的模型上出现，且模型越大越明显。

## 关键先例发现：LoopUS —— Qwen3 后训练循环化已被验证（2026-09-19 追加）

用户指出终极目标是 Qwen3.8-27B 循环化，搜索发现直接先例：

**LoopUS: Recasting Pretrained LLMs into Looped Latent Refinement Models**
（釜山国立大学，arXiv:2605.11011，2026-05）
- 代码：github.com/Thrillcrazyer/LoopUS；模型：HF `Thrillcrazyer/Qwen3_1.7B_LoopUS`
- **底模就是 Qwen3 系列**：Qwen3-1.7B / 4B / 8B + TinyLlama + Phi-4 14B
- **训练量仅 3B token**（FineWeb-Edu，ctx 1024）——对比 Relaxed Recursive 60B / McLeish 52B
- 效果（zero-shot）：Qwen3-4B 平均 +1.8pp（ARC-C +3.6、OBQA +5.0），ppl −15~20%，
  深度 40/80/100 外推仍稳定；自适应平均深度 3.39/8
- 同预算对比（TinyLlama）：LoopUS 3B token +6.3 > Bae(Relaxed) 60B +3.5 >
  McLeish 52B **−2.9**（粗暴课程改造反而掉点——与本项目 V1 失败同构）

**V1 失败根因的精确对照**（LoopUS 四组件 vs 我们的实现）：
1. 块选择：按隐状态余弦距离的"分段动态"选层 ↔ 我们拍脑袋选 24–29
2. 选择性门：h←α⊙M(h)+(1−α)⊙h，α∈(0,1) 逐 token/通道阻尼插值
   ↔ 我们只有 LatentInjection 重注入 h₀，无阻尼 → 表征漂移
3. 随机深监督：B=20 只采样 K=5 个深度回传，其余 no_grad+detach
   ↔ 我们全深度回传（内存大且梯度耦合）
4. 单调性损失 L_mono=SiLU(L^(b)−L^(b−1)) 惩罚"越循环越差" + 置信头
   （token 准确率软标签 BCE，即视频退出口方案）↔ 我们完全没有 → 深度增益为负无人管

**结论修正**：旧结论"后训练循环化需 60B token"不成立——**配方正确时 3B token 足够**。
Qwen3.8-27B 循环化可行性：14B（Phi-4）已验证 +1.7pp，27B 无已知障碍；
服务器成本估算 3B token × 27B ≈ 4×A100 1–2 天（原估 4 天砍半）。
增益量级需诚实：+1.6~+2.2pp 平均（推理类任务 +3~5pp），非"逼近思考模式"的跃迁。

**本机下一步**（V2 方案据此重定向）：下载 Qwen3_1.7B_LoopUS 复现深度曲线 →
对照源码改造 recurrent_qwen.py（选择性门+单调性损失+随机深监督）→
在 Qwen3-4B（我们已有底模）上重跑 LoopUS 式训练。
