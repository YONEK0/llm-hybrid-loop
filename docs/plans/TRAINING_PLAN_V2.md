# 本机深度循环验证方案 V2′（底模已更换）

> 本文件是 V2′，取代更早的 V2 草案（旧版沿用非循环底模，逻辑自相矛盾，已废弃）。
> V2′ 自身随后也被 V3 → V4 → V5 取代，此处仅作历史存档；文中"60B token"为 V1 时期估算。

## 一、为什么旧 V2 是错的（回应质疑）

旧 V2 仍用 Qwen3-4B（非循环底模）做后训练改造。但我们自己的结论就是：
**循环块的不动点性质必须在预训练中习得，后训练造出来等于重做预训练
（Relaxed Recursive 也要 60B token，本机差 5–6 个数量级）。**
在这个结论下，换迭代嵌入、换课程、换损失加权都只是"更精致地撞同一堵墙"——
V2 唯一能辩护的是"区分根本不可行 vs 工程细节失败"，但 Relaxed Recursive 的
先例让这个辩护期望价值极低：失败了只确认已知，"成功"了按我们的前科还得先
怀疑测错。

**结论：底模必须换。**要验证"后训练强化循环推理"，前提是底模已经有循环块。

## 二、新底模：Ouro-2.6B（本机已有、已跑通）

| 项 | 状态 |
|---|---|
| 循环能力 | ✅ 预训练习得（7.7T token，48 层×4 循环） |
| 本机推理 | ✅ 已跑通（ouro_env，3–4s/题） |

## 三、V2′ 验证的问题（一句话）

**对"预训练循环模型"做本机可负担的后训练（门校准 / LoRA SFT / CoT→隐空间蒸馏），能否提升或至少不破坏其隐空间推理的深度增益？**

这是 V1 全程没碰过、且不被预训练算力墙挡住的方向。三个子问题：

- Q1 退出门校准能否在零训练成本下优化"深度-准确率"Pareto？（视频阶段二配方，
  在 Ouro 上 I(t) 信号理应为正——与 Qwen3 上的负信号形成干净对照）
- Q2 LoRA SFT 会不会破坏预训练的循环性质？（服务器 uptrain 的前置风险问题：
  若 SFT 后深度曲线变平，60B uptrain 必须带循环正则；若保持，则轻量适配可行）
- Q3 显式 CoT 能否蒸馏进隐空间迭代？（Coconut 式课程，Ouro 是比 Qwen3 合适
  得多的底模——它有循环块可承接）

## 四、阶段设计

### Phase 0：纯推理诊断（零训练风险，半天，先做）

1. **GSM8K 基线 + 深度曲线**（现有 `eval_ouro_depth.py` 改数据源）：Ouro 只测过
   ProsQA，GSM8K 上深度增益是否存在是空白。
2. **退出门信号标定**：跑满 4 轮、记录每轮 CE，画 I(t)=max(0,ℓ(t−1)−ℓ(t)) 分布。
   预期为正（Qwen3 上实测为负）——直接验证视频配方的适用边界。
3. **误差分析**：ProsQA 错的 47% 分类（循环不足 / 知识缺失 / 格式问题），
   决定 Phase 1 训练目标。

**判定门**：若 GSM8K 上也有深度单调增益 → 全速推进；若只在 ProsQA 有 →
结论写明"循环增益任务依赖"，仍推进但预期下调。

### Phase 1：退出门阶段二校准（零主干训练，1–2 小时）

- 视频配方：冻结主干，I(t) 构造软标签 w=σ(k(I−τ))，对 `early_exit_gate`
  （linear(hidden,1)，Ouro 已有此模块）做 BCE。
- 产出：自适应深度 vs 固定深度的 Pareto 曲线（严格评分）。
- 成功标准：自适应深度的准确率 ≥ 固定 depth4 的 95%，平均深度 < 4
  （省算力不损精度即为正结果）。

### Phase 2：LoRA SFT 可训练性 spike + 循环保持实验（半天，有 OOM 风险）

1. 先做 **spike**（30 分钟）：ouro_env 下 Ouro-2.6B + rank-8 LoRA + batch 1 +
   梯度累积，测峰值显存。8GB 若 OOM → 降级为 1.4B 或只做推理侧结论。
   （风险：Ouro 自定义建模代码 × 4bit/LoRA 兼容性未知，spike 就是去验证的。）
2. 小规模 SFT（≤600 步）：目标由 Phase 0 误差分析定（大概率是 GSM8K 数字格式
   或 ProsQA 答案格式适配——最弱、最不会伤循环性质的信号）。
3. **核心测量**：SFT 前后的深度曲线对比（严格评分）。
   - 保持单调 → Q2 正面答案：轻量适配不破坏循环性质；
   - 曲线变平 → Q2 负面答案：uptrain 必须保护循环结构（同样是重要结论）。

### Phase 3：CoT→隐空间蒸馏（Coconut 课程，半天，可选）

- 用 Ouro 自己 depth-1 时生成的显式推理文本（我们已观察到它退化成文本 CoT）
  作为数据，课程式逐步替换为"少 token + 多迭代"：
  keep CoT 步数 3→2→1，同时要求 depth 4——模型被迫把删掉的推理搬进隐空间。
- 底模有循环块，这是 Coconut 实验第一次处于"正确底模"下。
- 成功标准：keep=1+depth4 的严格 EM 比 keep=3+depth1 不降超过 3pp
  （即删掉的 2 步推理被隐空间承接）。

## 五、验收标准

| 等级 | 标准 |
|---|---|
| Phase 1 达成 | 自适应门 Pareto 优于固定深度（准确率持平且平均深度<4） |
| Phase 2 达成 | SFT 后深度单调性保持（Δ(d=4 vs 1) 不缩水超过 1/3） |
| Phase 3 达成 | CoT 压缩 2 步不损严格 EM（>−3pp） |
| 任何负结果 | 写入 PROJECT_REVIEW V2′ 附录，直接服务服务器方案设计 |

明确不做的事：**不再测"绝对分数逼近底模"**（Qwen3-4B 64% 天花板与 Ouro 2.6B
不是同量级模型，横向比无意义）；**不再对非循环底模做任何改造训练**。

## 六、预算与风险

| 阶段 | GPU 时间 | 主要风险 |
|---|---|---|
| Phase 0 | ~3h 纯推理 | 无 |
| Phase 1 | ~1.5h（只训 1 个 linear） | 几乎无 |
| Phase 2 | spike 0.5h + 训练 3h | OOM / 自定义代码×LoRA 不兼容（spike 提前暴露） |
| Phase 3 | ~3h | 依赖 Phase 2 的训练通路 |

总计 ≈ 1 天，全部 8GB 内（推理 3–5GB，LoRA spike 后定论）。

## 七、对服务器路线的价值

- Phase 1 的门校准配方 → 直接并入 60B uptrain 方案（已写 `../reports/RECURRENT_DEPTH.md`）；
- Phase 2 的循环保持结论 → 决定 uptrain 要不要循环正则 / 深度采样课程；
- Phase 3 的蒸馏课程 → Coconut 式数据配比的本地预演。
